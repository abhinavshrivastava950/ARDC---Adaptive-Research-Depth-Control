An AI research assistant that knows when to stop

This project — the Contract-Gated Lease Controller (CGLC) — fixes effort miscalibration: AI assistants that quit before reading the key document, ramble on long after the answer is solid, or dig deeper in the wrong direction. Everything below runs live in this page — no backend, no setup.

1 · The problem we solve

Imagine asking an AI: "Compare these three system designs from the attached documents and tell me which is strongest." Three things routinely go wrong:

🛑 Quitting too early

The answer sounds confident but never read the third document. Nobody notices — it looks finished.

🔁 Rambling too long

The answer was solid after 3 searches, but the assistant does 12 more "just to be thorough" — burning time, money, and your patience.

🧭 Wrong direction

All the evidence is in a different set of documents, but the assistant keeps re-phrasing the same failed search instead of pivoting.

Today's fixes are crude: max_tokens, "be thorough but concise", or a fixed number of searches. None of them can tell done apart from stuck apart from blocked. That distinction is what this project adds.

2 · The idea, in one analogy

Think of a research assistant and a manager:

👩‍💻 The worker (assistant)

Reads documents, searches, drafts the answer. Good at research — bad at judging when to stop (like most of us).

🧑‍💼 The controller (manager)

Never does the research itself. It writes a contract (what "done" means), hands out small leases ("do up to 3 searches toward this gap, then report back"), and checks the work at each checkpoint.

✅ The gate (checklist)

Finishing requires a checklist: a draft exists, all required reading is done, every key claim has evidence, the format is right, nothing is blocked. One unchecked box = no finish.

The golden rule: finishing is about the checklist, never about "I feel done" or "I've searched enough." Effort decisions (keep going? verify? change direction?) use cheap signals plus a cost-benefit score — and can never override the checklist.

3 · How it works, step by step

  1. Write the contract. Before any research: goal, must-do steps (e.g. "read all three designs"), claims needing evidence, required answer format. → code: contracts.py
  2. Grant a lease. "You may do up to 3 actions toward closing gap X." Leases are SHORT (1), STANDARD (3) or EXTENDED (5). A lease is permission for one intent — never a blank cheque. → leases.py
  3. Worker acts; everything is logged. Each search/reading is appended to an immutable trace with its cost. No interpretation yet — just facts. → trace.py
  4. Checkpoint fires on events only — worker asks to finish, lease runs out, same search repeats with nothing new, a contradiction appears, budget gets tight. Not after every step (that's the expensive mistake others make). → guards.py
  5. Decide: checklist first, effort second. If every checklist box passes → ALLOW_FINALIZE. Otherwise rank the options — keep going, double-check a claim, or pivot — by value per cost and grant the next lease. If nothing can proceed: ask the user, or report blocked (an honest "I can't finish", never dressed up as success). → controller.py, scoring.py, gates.py

How "stuck" is detected (cheaply): if the last p searches look almost identical (J ≥ tau_J) and bring almost nothing new (UPR ≤ tau_U), the lease ends and a checkpoint inspects. That signal means "look closer" — never "we're done". → stagnation.py

6 · How we'd know if this is wrong (proof, not promises)

The design states its own kill criteria — if any of these turn out true, the controller isn't earning its keep:

  • A plain "be thorough" prompt or a fixed search budget matches it on quality.
  • The controller's own cost eats the time/money it saves.
  • Unsupported or premature answers increase.
  • Pivoting never beats "just search more in the same place".

Planned comparisons: uncontrolled worker → fixed-shallow / fixed-deep budgets → generic prompt → fixed checkpoints → CGLC without stall detection → CGLC without scoring → full CGLC. Measured on correctness, checklist compliance, evidence grounding, user time, system cost, and controller mistakes (false finish, false block, wrong pivot). → code: src/cglc/evaluate/, tests: pytest -q (18 tests).
