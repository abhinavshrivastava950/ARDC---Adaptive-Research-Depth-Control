1 · Problem

Capable assistants, uncalibrated effort

Ask an AI: "Compare these three system designs from the attached documents and tell me which is strongest." Three failure modes recur:

Under-execution

The answer sounds confident yet never inspected the third document. Premature completion can be clean — that is what makes it dangerous.

Unproductive continuation

The answer was supportable after 3 retrievals; the agent performs 12 further searches with no marginal gain — cost without progress.

Misdirected effort

The evidence lies in a different source family, but the agent keeps re-phrasing the same failing query rather than redirecting.

Existing remedies — token caps, "be thorough but concise", fixed iteration budgets — cannot distinguish completion from local stagnation from blocked termination. This project makes that distinction architectural.

2 · Idea

Separate permission from completion

The worker

Plans and executes research: queries, reading order, drafts. Retains full autonomy within each grant of work.

The controller

Owns the task contract, grants bounded leases (one coarse intent, 1–5 actions), and interprets semantics only at checkpoints — never after every action.

The gate

Finalization requires a conjunction: draft exists ∧ process duties met ∧ evidence sufficient ∧ schema conforms ∧ no blocker. One failure denies completion.

Architectural rule. Hard obligations constrain what is allowed · semantic sufficiency governs whether the answer is ready · stagnation and value-per-cost govern what to do next. These three functions are never collapsed into one score.
3 · Method

Five steps per run

  1. Compile the contract K = (g, H_proc, H_evid, S_soft, B_mat, A_schema, B_policy). V1 uses benchmark/user-confirmed obligations. → contracts.py
  2. Issue a lease ℓ = (intent, gaps, actions, cap, progress-test). SHORT 1 · STANDARD 3 · EXTENDED 5. → leases.py
  3. Log the trace. Every action, observation and cost appended immutably; no semantic reconstruction. → trace.py
  4. Checkpoint on events — finalization request, lease expiry, p-round structural stall, blocker/contradiction, budget tier, max silence. → guards.py
  5. Gate, then rank. Conjunctive gate first; then rank feasible CONTINUE / VERIFY / REDIRECT by value-per-cost r = max(0,u)/(d+ε). Terminal states selected by condition, never by score. → controller.py scoring.py gates.py
Stagnation trigger (CGDP): over p consecutive rounds, action similarity J ≥ τJ with retrieval novelty UPR ≤ τU ends the lease and forces inspection. It establishes local stall — never global exhaustion, never completion. → stagnation.py

    STEP 3Ask, and say what must be proven

    The controller will not approve an answer until every requirement below has a supporting quote.

    Advanced
    How to read the result: plain-English glossary
    Worker
    The AI that does the research: it searches your documents, quotes them and drafts the answer.
    Controller
    A separate referee. It never writes the answer; it decides how long the worker may keep going and whether the result may be called done.
    Lease
    A short, bounded permission to work (1 to 5 steps) on one goal. When it runs out, the controller checks in.
    Checkpoint
    A moment where the controller inspects the work. It happens when the worker asks to finish, a lease ends, the worker starts repeating itself, sources conflict, or the budget gets tight, not after every step.
    Gate
    One of five yes/no checks that must all pass before an answer is approved. Failing any gate means “not yet”, however confident the answer sounds.
    Evidence / receipt
    A verbatim quote from your documents that backs a requirement. Quotes that do not really appear in the document are thrown away.
    Stall
    The worker keeps searching nearly the same thing and finds no new passages. That triggers a checkpoint; it does not mean the answer is done.
    Continue / Verify / Redirect
    The controller’s options when the answer is not ready: keep going; double-check a weak or disputed claim; or change approach because the current direction stopped paying off.
    Approved vs. stopped
    “Approved” means every gate passed. “Stopped” means the limits were hit first, and the draft is shown clearly marked as unapproved.
    RAG mode
    For big inputs the AI does not read everything at once. It writes a search query, a keyword search returns the best passages, and it reads only those.
    Offline mode
    No AI at all: keyword search plus simple rules. It exists only to show the controller’s behavior on your text.

    7 · Evaluation

    Falsification criteria

    The design is a hypothesis until measured. It fails if any of the following hold:

    • A generic "be thorough" prompt or fixed budget matches CGLC on quality, obligation coverage and user time.
    • Controller overhead eliminates the cost saved by prevented over-execution.
    • Premature or unsupported finalizations increase versus baselines.
    • REDIRECT decisions do not improve recovery over continued same-direction budget.

    Comparison ladder: uncontrolled worker → fixed-shallow / fixed-deep → generic prompt → fixed checkpoints → CGLC∖stall → CGLC∖scoring → full CGLC. → src/cglc/evaluate/ · pytest -q.
